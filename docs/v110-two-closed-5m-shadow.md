# №110 — ранний 1М-прогноз и две ПОЛНЫЕ закрытые 5М-свечи

**Решение владельца:** исследовать схему «ранний 1М → первая целиком завершённая 5М → вторая целиком завершённая 5М», чтобы понять, где пятиминутная торговля получает полезное раннее предупреждение и где ожидание слишком запаздывает.

### Что уже работает (не меняем)
- **№108 вход** независимо читает закрытые свечи **5М и 15М**, проверяет цену, объём, уровень, расходы и срок действия. Не разрешает автосделки.
- **Отдельный Forecast ntfy** читает закрытые **1М, 5М и 10М** и публикует наблюдение только при согласованном направлении, плюс фильтры RSI/объёма/опоздания. Не равен входу 5М.
- **Ранний 1М / PRE_BREAK** отдельный поток диагностики и предиктор; не следует считать единичную красную минутную свечу подтверждённым SHORT.
- Сохраняем все действующие уведомления, лимиты, ntfy, MA, торговые настройки и №110 ML без изменения.

### Что изучает новая модель
`lib/v110-two-5m-continuation.mjs` использует только настоящий опубликованный Forecast из существующего зашифрованного архива. `aligned5m[1,2,3]` — результат закрытия на первой, второй и третьей следующих пяти-минутных **границах**, отсчитанный от исходной цены уведомления. Важная тонкость: на первой границе может закрыться свеча, которая началась **до** отправки ntfy. Поэтому:

1. `aligned5m[1]` — только опорная граница, НЕ первая полноценная новая 5М-свеча.
2. **Первая целиком будущая 5М:** `aligned5m[2]-aligned5m[1]`. Это движение от первого закрытия к следующему.
3. **Вторая целиком будущая 5М:** `aligned5m[3]-aligned5m[2]`. Два позитивных для заранее указанного LONG/SHORT знака подряд + чистое положительное движение относительно цены уведомления к третьему закрытию = консервативное описательное подтверждение.

Эти числа — направленные **close-to-close** сдвиги в bps, не цвета тела/фитиля 5М. Это специально избегает неверного вывода о предыдущей части свечи и не моделирует точку исполнения сделки. Все три закрытия должны быть OBSERVED, завершены до текущего времени. Если нет свечей, это UNKNOWN, а не WIN. Дубликаты одного сообщения игнорируются, один инструмент учитывается не чаще чем раз в 30 минут.

Считаем отдельно LONG/SHORT, STRONG/STANDARD/CAUTION, случаи уже пройденного в сторону прогноза движения ≥0,10% за 5 минут **до уведомления**, первое достижение +0,10% до/после окончания двух 5М, долю обоих последовательных движений и медиану ожидания второго закрытия. При слишком маленьких группах UI скрывает проценты. Результат показывает только описание исторических прогнозов, **никакой сетап не подключён к live**.

### Критические ограничения

- Две полные закрытые 5М после уведомления неизбежно дают задержку обычно **около 10–15 минут** и могут пропустить самое раннее движение. Эта проверка нужна для выбора этапа, а не для обязательного затягивания реальных сигналов.
- Исторический архив содержит **только уже отправленные** Forecast (часто 1М/5М/10М уже совпадали). Он **не содержит полную выборку минутных падений против растущего 5М**, потому что такие случаи отсеиваются до уведомления. Поэтому из одного этого исследования НЕВОЗМОЖНО доказать, как часто 1М шумит против 5М. Для честного теста понадобится отдельное заранее фиксированное shadow-наблюдение всех кандидатов, включая **не отправленные**, без дополнительных рыночных запросов, если возможно.
- Это **не** независимая prospective проверка точности, не net P&L и не рынок без сигналов для сравнения. Даже высокий процент двух совпавших 5М не даёт основания переключать действующие правила №108, менять торговые уведомления, автоторговать или проводить paid API calls.
- Никаких новых cron, URL интеграций, платного ML API или локальных файлов. Используются уже существующие `/api/signals?mode=journal`, OIDC writer и `/history.html` — только агрегаты, без раскрытия приватных записей/секретов.
