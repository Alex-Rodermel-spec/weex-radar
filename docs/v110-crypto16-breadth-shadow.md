# №110: состояние крипторынка из уже имеющихся закрытых свечей WEEX (15.11.2026)

**Контекст пользователя:** два снимка Crypto Bubbles / WEEX в районе 03:33–03:34 Berlin показали почти все красные монеты и «Fear & Greed = 11», заявленную общую капитализацию −5,06%, доминирование BTC 59,40%. В то же время XRP сделал сильный внутриминутный отскок. Это выбранный постфактум пример; он НЕ доказывает, что индекс страха или число красных пузырей предсказывает цену. Разные проценты на экранах могут относиться к разным периодам.

## Что реально добавлено

При **существующем 10-минутном запуске** `runForecastNotifications` собирается `researchObservations` из 32 WEEX инструментов. Добавлены только две чистые операции:
- `standalone-forecast.mjs` включает `lastCandleBodyBps` (закрытие последней ПОЛНОЙ свечи соответствующего ТФ относительно её открытия, со знаком) в уже вычисляемые 1М/5М/10М данные;
- `v110-crypto-breadth-shadow.mjs` считает только **16 настоящих криптоинструментов**: BTC/ETH (2), альткоины (11), мемкоины (3). Оставшиеся 16 инструментов (металлы, валюты, акции) НЕ смешиваются с процентом растущих/падающих криптовалют. Все 16 должны иметь достоверную ЗАКРЫТУЮ 5М свечу с **одним и тем же временем закрытия**, иначе `INCOMPLETE_CRYPTO16_COHORT`, `regime:UNKNOWN`, проценты не публикуются.

Данные только наблюдательные: число растущих, падающих, плоских закрытых 5М свечей; медиана signed body в bps; отдельные счётчики 5М-индикаторного направления (LONG/SHORT/NEUTRAL); расхождения 1М с 5М; медиана и полнота по классам BTC/ETH, альты, мемы; сопоставление XRP против медианы 16 криптовалют; контекст BTC/ETH. **Широкое падение** определено неизменным заранее инженерным правилом «>=12 из 16 криптовалют имели отрицательную свечу», аналогично рост. Это НЕ оценка вероятности, торговый вход, срабатывание фильтра или сигнал о ликвидности.

В стандартном результате `runForecastNotifications` появляется **`cryptoBreadthResearch`** рядом с `oneToFiveResearch`. Новых WEEX запросов, cron, ntfy-сообщений, модели с платным API или записи Blob **нет**. Основной №108 и торговые alert gates не меняются. Старые скриншоты не могут быть использованы как timestamp-aligned исследовательский источник. Поля `Fear & Greed`, market cap, dominance, суточные Crypto Bubbles НЕ подтягиваются — их нельзя без верификации исторической привязки сравнивать с будущими рынками. Значение «11» на скриншоте остаётся помеченным только как `OWNER_SCREENSHOT_UNVERIFIED` в исследовательской задаче №141, НЕ в автоматических данных.

## Как получить настоящую оценку пользы

1. Не выбирать пороги по событиям XRP задним числом. Сохранить заранее зарегистрированные группы (широкое падение / широкий рост / смешанный рынок / неполные данные), 1М против 5М LONG/SHORT, не путать индикаторный bias с направлением свечи.
2. В отдельном будущем протоколе фиксировать на каждое наблюдение 16-крипто breadth, инструмент, прогнозный timestamp, candle close timestamp, состояние 1М/5М и цену закрытой 1М, а затем только **после** сравнивать 5/10/15 минут и две ПОЛНЫЕ следующие 5М свечи. В текущем PR нет нового долговременного журнала и ещё **нет** такой парной связи с будущими исходами.
3. Контроль: одинаковые часы и рыночная волатильность, BTC/ETH движение, длительность тренда, выбор вручную отправленных скринов, ложные пробои и комиссии/проскальзывание. Одна коррелированная паника на 16 монет — не 16 независимых испытаний.
4. Публиковать только число наблюдений, а доли успешного раннего прогноза при n<20 скрывать; выделить отдельный будущий holdout без изменений модели во время оценки.

**Статус:** измерение breadth в уже существующем 10М контуре, ПРИГОДНО как контекст для дальнейшего исследования; нет доказательств улучшения доходности, нет нового торгового фильтра.


## 15.11.2026 · устранён риск устаревшего режима (исследовательский патч)
В Vercel runtime были два последовательных запуска прогноза **10:50 и 10:51 UTC**. Оба получили 16/16 крипторынков, но первый `cohortClosedAt=10:40 UTC` (старый 5М бар), второй `cohortClosedAt=10:50 UTC` (актуальный). Они показали 16 зелёных и 16 красных свечей соответственно. Нельзя выдавать их за противоположные фазы **одной и той же** закрытой 5М свечи; это свечи разных периодов. Большой анти-лаг допуск в отдельном `readStandaloneForecast` (до ~11 минут) был приемлем для чтения трендовых индикаторов, но слишком велик для ярлыка **текущей** рыночной ширины.

Исправлено: `summarizeV110CryptoBreadth` теперь требует, чтобы `five.closedAt===floor((scanAt-1000)/300000)*300000` для каждого из 16 активов. Если WEEX ещё не предоставил последние закрытые 5М данные, результат **INCOMPLETE/UNKNOWN**, даже если все 16 старых 5М баров прекрасно синхронизированы. Показываем `latestExpected5mCloseAt` для независимой диагностики. Имеющиеся старые наблюдения не переклассифицируются; новых рыночных запросов, cron, дополнительных сообщений, боевых фильтров нет.
