# WEEX RADAR — GitHub + Vercel

Read-only dashboard for WEEX Futures with Bybit fallback. No API keys, no orders, no connection to your trading account.

## Развёртывание из GitHub

1. На Vercel импортируйте GitHub-репозиторий `Alex-Rodermel-spec/weex-radar`.
2. Framework Preset: `Other`. Root Directory: `/`. Build command можно оставить пустым.
3. Deploy. Проверяйте `/api/signals` и страницу. GitHub-репозиторий и уже существующий проект Vercel не связываются автоматически.

## Как работает

- Каждые 60 секунд, **пока страница открыта**, обновляет данные с `/api/signals`.
- Источник **WEEX** для 5м + 15м. Если хотя бы один запрос неудачен / устарел, переключается **целиком на Bybit**.
- Поддерживает BTC, ETH, XRP, SOL, ALGO, SHIB, DOGE, XAUT (золото на базе XAUT).
- Анализирует **только закрытые** 5-минутные свечи, подтверждает EMA-тренд 15 минут и пробой диапазона.
- Сигнал действителен **до трёх минут после закрытия** сигнальной свечи. После этого `ЖДАТЬ`.
- Сильный сигнал выделяется фиолетовым; обычный — отдельно.
- Отображаемые TP/SL — иллюстративные уровни ATR, а не биржевые ордера.
- Включение уведомлений браузера необязательно. Уведомления возможны **только пока страница активна** (в фоне не гарантируются).

## Важно

Это прототип без реальной статистической проверки/бэктеста стратегии. Сигнал не гарантирует доход и не является подтверждением цены исполнения на бирже. Не торгует автоматически. Для круглосуточной рассылки push/Telegram понадобится отдельный фоновой планировщик и сервис доставки; простой веб-сайт этого не обеспечивает.

## Фоновые push для Android

Сайт использует Web Push и service worker (`/sw.js`). Подписки сохраняются в отдельном **private Vercel Blob** store. В репозитории нет VAPID-private key, токенов хранения или секретов.

- Откройте https://weex-radar.vercel.app **в Google Chrome на Android**. Нажмите кнопку «🔔 Включить push в фоне» и разрешите уведомления.
- При первой подписке отправляется **тестовое уведомление**. Его получение зависит от Android/браузера, режима «Не беспокоить» и энергосбережения.
- Проверки из GitHub Actions выполняются по расписанию **раз в 5 минут**; GitHub может задержать или пропустить плановый запуск. Сигналы действуют 3 минуты, поэтому некоторые сигналы неизбежно будут пропущены.
- GitHub Actions использует **OIDC** без статических секретов и вызывает защищённый `POST /api/push-dispatch`. Также поддерживается `x-radar-cron-key` для доверенного внешнего планировщика (например, cron-job.org, каждую минуту), но его нужно подключить отдельно.
- Нужные переменные Vercel в Production: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `BLOB_READ_WRITE_TOKEN`, `PUSH_CRON_KEY`.
- Сайт **не гарантирует** доставку push за конкретное время, не отправляет сделки на биржу и не гарантирует прибыль.

Все исходные файлы находятся в GitHub. Пока проект Vercel **не привязан к GitHub для автоматического деплоя**: изменения в репозитории не опубликованы до отдельного развёртывания.

## Подготовка ручного подтверждения реальных сделок

Откройте `/trade.html` для просмотра **исключительно предварительного** плана сделки (50 USDT × 10, до 3 разных символов). Страница и `GET /api/trade-preview?symbol=XRPUSDT` проверяют только свежие сигналы WEEX, котировку и рыночные ограничения, дают примерные уровни SL/TP и оценку риска. **Никаких ордеров они не размещают.**

Это первый этап, а не работающий торговый терминал. Полномочия и API-ключ WEEX пока не подключены; подтверждение и серверное исполнение остаются выключенными. Не размещайте API Secret, Passphrase или токены в репозитории. Следующим этапом нужны отдельный ключ с разрешением Futures, строгая аутентификация пользователя, атомарная защита от повторов и параллельных ордеров, проверка реальных позиций WEEX, тестирование на симуляции и явное включение live-режима.

Существующие `/api/signals`, `/api/push-dispatch`, сервис-воркер и cron не меняются.

## Защищённая проверка WEEX API без сделок

Endpoint `POST /api/weex-connection-check` является диагностическим и проверяет подпись V3 и доступ к `GET /capi/v3/account/accountConfig` через WEEX. Он **не запрашивает баланс** и **не размещает ордера**. Ответ содержит только общий результат авторизации, без информации аккаунта.

Для вызова требуется `x-radar-cron-key` с действующим `PUSH_CRON_KEY`; посторонние запросы получают HTTP 401. Не помещайте ключ в URL, браузерный JavaScript, GitHub, общедоступные скриншоты и логи. Три `WEEX_API_*` секрета должны быть установлены в Vercel **Production**; при недостающих значениях диагностика возвращает 503. После изменения Production env требуется новое Production deployment, но развёртывание не должно менять работу push и cron.

Созданный ключ может быть read-only — успешная авторизация **не** означает, что ключ имеет разрешение торговли фьючерсами, и не служит разрешением отправлять реальные сделки. Для live-режима потребуется отдельный аудит безопасности и явное включение; `WEEX_TRADING_ENABLED=false` оставляем.

## Реальные сделки с ручным подтверждением (V3; заблокировано по умолчанию)

На `/trade.html` есть 3 шага: проверка счёта, получение одноразового плана и осознанное подтверждение. Бот перед отправкой `POST /capi/v3/order` перепроверяет только свежий сигнал **WEEX**, котировку, доступную USDT-маржу, открытые позиции, ожидающие ордера, количество/точность контракта и риск до 10 USDT (без комиссий и проскальзывания). Использует `50 USDT × 10`, исключительно ISOLATED 10×, максимум 3 разные монеты, idempotent `newClientOrderId` на свечу, **одним ордером MARKET с прилагаемыми `slTriggerPrice` и `tpTriggerPrice`**. Режим Bybit никогда не используется для торговых приказов.

Важно: реализация **не активируется** без `WEEX_TRADING_ENABLED=true`, `WEEX_CONFIRM_EACH_ORDER=true`, `WEEX_MARGIN_USDT=50`, `WEEX_LEVERAGE=10`, `WEEX_MAX_OPEN_POSITIONS=3` и отдельного `WEEX_TRADE_APPROVAL_PASSWORD` длиной минимум 20 символов (задаётся пользователем только через Vercel Sensitive Environment Variable в Production). Не используйте пароль WEEX и API Passphrase как пароль подтверждения. При неверном пароле, другом сайте, закрытом рынке, устаревшем сигнале и отсутствии разрешения Futures ордер не отправляется. Новые env-переменные требуют нового Production-развёртывания для применения.

После нажатия «Подтвердить реальную сделку WEEX» создаются атомарные приватные Vercel Blob-записи блокировок по сигналу и глобальному выполнению. Если ответ биржи не однозначен, глобальная блокировка **остаётся**, предотвращая дублирование. Даже если ордер принят, разблокировка следующей сделки требует **личной проверки наличия SL/TP внутри WEEX** и явного подтверждения на странице. Отсутствие API подтверждения установки защитных ордеров не даёт гарантии их существования. При ошибке отправки или неясном статусе позицию и SL/TP следует немедленно проверить на WEEX; нельзя просто отправить запрос повторно.

Срок одноразового плана максимум 45 сек. Участки `api/push-dispatch.mjs`, `api/signals.mjs`, `sw.js`, `.github/workflows/push-notifications.yml` не изменяются. Никаких токенов аккаунта или паролей в исходниках нет. Перед настоящей торговлей надо проверить WEEX V3 с API Futures permission; текущий API-ключ создавался с правом Read. Мы не отправляем живой ордер для проверки установки.

### Восстановление после сбоя
Проверить реальные позиции и защитные ордера непосредственно в WEEX, перед любыми попытками разблокировки. Глобальный приватный блокировщик `trading/execution-global.lock` намеренно не имеет автоматического TTL: после неизвестного результата нужно ручное исследование, иначе новая сделка может превысить лимиты.
